# v1 RC 통합 QA 실행 가이드

> **이 문서의 역할** — [#100](../../issues/100)이 "무엇을 확인할지(what)"의 목록이라면,
> 이 가이드는 **"어떻게 돌리고 증거를 어떻게 남길지(how)"** 의 실행 문서다.
> QA 결과는 워드/한글 파일이 아니라 아래 **§5 증거 템플릿**을 복사해 **#100 이슈 댓글**에 남긴다.

---

## 0. 언제 돌리나

릴리스 직전 한 번이 아니라 **각 릴리스 후보(RC) 빌드마다** 실행한다. 코드가 바뀌어 새 빌드를
올릴 때마다 이 절차를 다시 돈다(특히 배포가 걸린 `dev` 병합 이후).

---

## 1. 무엇이 "QA"이고 무엇이 아닌가 (혼동 방지)

우리 저장소의 "테스트" 관련 자산은 3층으로 나뉜다. QA(이 가이드)는 그중 **③ 수동 통합 검증**이다.

| 층 | 무엇 | 누가/언제 | 이 가이드와의 관계 |
|---|---|---|---|
| ① 자동 테스트 코드 | `app/tests/` (pytest), 안드로이드 unit test | **CI가 매 푸시 자동 실행** | 전제 조건. §2에서 "CI 초록" 한 줄로 확인만 한다 |
| ② seed 스크립트 | `scripts/seed_mission_templates.py` | QA/시연 **전에 1회 주입** | 사전 준비(데이터 세팅). QA 시나리오 자체는 아니다 |
| ③ 수동 통합 QA | 사람이 **실제 RC 빌드**를 조작하며 시나리오 확인·증거 기록 | RC 빌드마다 수동 | **← 이 가이드의 본체** |

즉 ①은 자동, ②는 준비물, ③이 사람이 손으로 도는 실제 QA다.

## 2. 사전 준비 (매 실행 체크)

- [ ] **RC 빌드 확보 + 빌드 SHA 기록**
  - Android APK 빌드:
    ```bash
    cd android
    export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
    ./gradlew --no-daemon :app:assembleDebug
    # 산출물: android/app/build/outputs/apk/debug/app-debug.apk
    ```
  - 빌드 SHA는 `git rev-parse --short HEAD` 로 기록해 증거에 남긴다.
- [ ] **서버 환경 확인** (RC 빌드는 `dev` 배포 서버 = EC2 를 가리킨다)
  - EC2: `t3.small`, 탄력적 IP `13.209.162.243`, 도메인 `aigo-health.duckdns.org` (HTTPS)
  - 기능적 확인: 앱에서 **체험으로 시작하기(게스트 로그인)가 성공하고 미션 목록이 뜨면** 서버·DB·nginx 정상.
- [ ] **② seed 데이터 주입** (미션이 떠야 QA 가능 — 걷기·운동·**단백질 식사**·게임)
  ```bash
  # 로컬/대상 DB를 향해:
  uv run --no-sync python -m scripts.seed_mission_templates
  ```
  - 멱등(같은 title은 건너뜀)이라 여러 번 실행해도 안전.
  - **배포 서버(EC2) DB에 주입하는 실행 위치·명령은 배포 담당(랑)과 확인** 후 진행한다.
- [ ] **① CI 초록 확인** — 대상 커밋의 GitHub Actions(checks)가 통과 상태인지 본다.
- [ ] **기기 준비**
  - 실기기 1대 이상
  - **시니어 UI 경계**: `320×568dp` + 시스템 글꼴 **최소 1.5배** 에뮬레이터(잘림·가림 확인용)
- [ ] **매 실행 처음부터 원칙** — 온보딩 완료가 영속되면 안 된다(한 폰으로 여러 명 테스트).
  각 시나리오 시작 전 **앱 데이터 삭제(또는 재설치)** 로 첫 실행 상태에서 시작한다.

## 3. 시나리오 체크리스트

각 항목은 **절차 → 기대 → ✅/❌** 로 확인한다. 목록은 #100과 1:1로 맞추되, 여기서는 재현이
헷갈리는 항목에 절차 힌트를 덧붙였다. **단백질 식사(§3.2 ★)** 는 신규라 절차를 온전히 적었다.

### 3.1 인증·세션

- [ ] Google/Kakao 신규 가입 → 약관 → 온보딩 완료 → 홈
- [ ] 앱 종료·재실행 시 승인된 소셜 세션만 정상 복원
- [ ] 약관 동의 전 종료 시 홈으로 우회하지 않음 (#153)
- [ ] 체험으로 시작하기 → 종료 → 재실행 시 시작 화면 (#153)
- [ ] 설정에서 로그아웃 → 같은 계정 재로그인 → 동일 user_id·기록 유지 (#154, #112)
- [ ] 토큰 없음/만료/401에서 로그인 화면이 **한 번만** 표시되고 성공 후 올바른 화면으로 복귀 (#88, #95, #112)
- [ ] 미션 탭 진입이 guest login을 호출하거나 로그인 계정·닉네임을 바꾸지 않음 (#160)
- [ ] Google/Kakao 취소·오프라인·공급자 장애 메시지 구분
- [ ] 릴리스 로그에 ID token·access token·건강정보 미노출

### 3.2 온보딩·홈·미션

- [ ] 체력검사에 유효한 5STS 시간을 입력한 경로와 명시적 스킵 경로를 각각 검증 (#155)
- [ ] 스킵은 기본 난이도, 유효 측정은 서버 규칙에 따른 난이도로 표시
- [ ] 레벨별 걷기 미션 정확히 1개
- [ ] 미션 탭 운동과 홈 운동이 같은 실제 운동 화면으로 이동 (#162)
- [ ] 0걸음·목표 미달 종료는 성공 축하가 아닌 중립 결과로 표시 (#161)
- [ ] 걷기 시작·목표 달성 TTS/진동이 각각 한 번만 발생하고 화면을 보도록 유도하지 않음 (#92, #148)
- [ ] 설정 저장 → 재실행 후 글자·소리·배경음악 유지 및 적용
- [ ] 홈 펫 말풍선이 긴 닉네임·최장 문구에서도 펫·홈 콘텐츠와 겹치지 않음 (#143)

#### ★ 단백질 식사 기록 (신규 — #224 백엔드 / #225 앱)

> 전제: 미션 목록에 **"단백질 식사 기록하기"** 가 뜨려면 §2 seed 주입이 되어 있어야 한다.
> 이 미션은 `requires_kidney_check=True` — **신장/단백질 제한 사용자에겐 노출되면 안 된다.**

- [ ] **안전 필터**: 건강체크에서 신장/단백질 제한(투석 등)으로 판정된 사용자의 미션 목록·홈에
      "단백질 식사 기록하기"가 **뜨지 않는다**. (직접 호출 시에도 서버가 403으로 막음)
- [ ] **일반 사용자 노출**: 제한 없는 사용자에겐 미션 목록에 정상 노출된다.
- [ ] **목표 달성(3종+)**: 서로 다른 카테고리 **3가지 이상** 선택 → 저장 → "목표 달성" 안내 +
      포인트 적립, 홈의 포인트·오늘 결과에 반영.
- [ ] **미달(1~2종)**: 2가지만 선택 → 저장 → `N / 3가지` 진행 안내(미적립), 홈 포인트 불변.
- [ ] **재진입 복원**: 저장 후 화면을 나갔다 다시 들어가면 **이전에 고른 카테고리가 그대로 선택**되어
      있고 편집(추가/해제)이 가능하다.
- [ ] **같은 날 재저장**: 카테고리를 바꿔 다시 저장해도 **포인트가 이중 적립되지 않는다**(오늘 기록 갱신).
- [ ] **시니어 UI**: `320×568dp` + 글꼴 1.5배에서 7개 카드 사진·라벨·버튼이 **잘리거나 겹치지 않고**,
      세로 스크롤로 저장 버튼까지 도달 가능하다.

### 3.3 오프라인·제거 기능·접근성

- [ ] 비행기 모드에서 APK 번들 준비운동 자산이 재생됨
- [ ] 온라인 전용·미다운로드 콘텐츠는 오류 화면 대신 연결 안내와 재시도를 제공
- [ ] 음성 입력 탭·프로브·온보딩 STT 진입점이 노출되지 않음 (#106)
- [ ] 흔들기 탭·데모 진입점이 노출되지 않음 (#108)
- [ ] 화면 이탈 후 흔들기 전용 센서 리스너가 동작하지 않음 (#108)
- [ ] `320×568dp`, 시스템 글꼴 최소 1.5배, 시스템 내비게이션 바에서 잘림·가림 없음
- [ ] **매 실행마다 빌드·환경·기기·결과 증거 기록** (§5)

## 4. post-v1 (현재 릴리스 비차단)

오프라인 캐시·outbox 동기화·재전송 멱등(#105, #91, #158) 계열은 **v1 릴리스를 막지 않는다.**
해당 기능 구현 후 #100의 "post-v1" 블록에서 검증한다. 이 가이드의 §3만 통과하면 RC로 본다.

## 5. 증거 템플릿 (복사 → #100 이슈 댓글에 붙여넣기)

```md
### RC QA 실행 — YYYY-MM-DD

- 빌드 SHA:            (git rev-parse --short HEAD)
- APK 종류:            debug / release
- 서버 환경 / API base: EC2 (aigo-health.duckdns.org) / dev 배포
- seed 주입:           ✅ / ❌
- CI(checks) 상태:     ✅ / ❌
- 기기·Android 버전:   (예: Galaxy S / Android 14)  +  에뮬 320dp·글꼴 1.5배

#### 결과
- 3.1 인증·세션:         ✅ N/❌ M   (실패 항목 번호·요약)
- 3.2 온보딩·홈·미션:     ✅ N/❌ M
  - ★ 단백질 식사:       ✅ N/❌ M
- 3.3 오프라인·접근성:    ✅ N/❌ M

#### 스크린샷·로그
- (경로 또는 첨부 링크)

#### 발견 이슈
- #___ (제목) — 블로커 여부
```

> 실패 항목은 **블로커 여부를 명시**한다. 릴리스를 막지 않는 것은 새 이슈를 남발하지 말고
> #100(post-v1) 또는 관련 백로그에 정리한다.
