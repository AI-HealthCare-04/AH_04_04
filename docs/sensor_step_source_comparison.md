# 걸음 소스 실측 비교 — 하드웨어 만보기 vs 가속도계 (이슈 #89 / #223)

> **목적:** #89의 "무권한 가속도계" 걸음 소스 결정을, **실측 근거를 가진 결정**으로 고정한다.
> #223(하드웨어 만보기 `TYPE_STEP_COUNTER` 전환 제안)의 검증 과정에서 나온 비교 데이터를
> 보존한다. 원본 로그는 리포 정책상 리포 밖 보관, **여기엔 요약만** 남긴다.
> 나중에 같은 제안(만보기 전환)이 다시 나올 때 이 데이터가 시작점이다.

- **관련 이슈:** #89 (걷기 게이트, 원 결정) · #223 (만보기 전환 제안, **철회**) · #176/K2 (가속도계 저속 개선)
- **측정 기기:** Samsung SM-F766N (단일 기기·단일 테스터, 자연 보행)
- **측정일:** 2026-07-28
- ⚠️ **읽기 전 전제:** 아래 만보기·가속도계 수치는 **같은 보행을 동시에 잰 paired A/B 가 아니라
  각각 별도 세션**이다(실 걸음 수·시간도 다름). 단일 기기·단일 테스터의 의도적 저속 보행이라
  **센서 간 절대 오차의 직접 비교나 65+ 일반화·펌웨어 내부 원인 규명에는 한계**가 있다(→ [§6 한계](#6-한계)).
  그럼에도 저속에서 만보기 과소계수의 **방향과 크기**는 결론(가속도계 유지)을 지지하기에 충분하다.

---

## 0. 요약 (한 줄)

**정상 속도만 보면 만보기가 우위(−2.4%)지만, 이 기기에서 대상 사용자에게 발생 가능한 느린·발 떼는
보행 시나리오에서는 하드웨어 만보기가 크게 과소계수(−84%)했고 가속도계는 −14%로 훨씬 나았다.**
→ 만보기 전환(#223) 철회, 가속도계(#89 원결정) 유지, 저속 개선은 K2(#176 돌출도 적응형)로.

---

## 1. 실측 결과 (SM-F766N, 별도 세션)

| 속도 대역 | 조건 | 만보기 (TYPE_STEP_COUNTER) | 가속도계 (현행) |
|---|---|---|---|
| **정상** | 3분20초, 실 250보 | 244 (**−2.4%**) | (4분 −24% / 10분 −22%) |
| **느린·발 떼는 보행** | 3분, 실 207보(만보기 세션)/169보(가속도계 세션) | **33 / 207 (−84%)** 💀 | **145 / 169 (−14%)** |

> **⚠️ 별도 트라이얼.** 느린 보행 행의 `33/207`(만보기)과 `145/169`(가속도계)는 **서로 다른 세션**으로,
> 실 걸음 수·시간이 다르다(paired A/B 아님). 센서 간 절대 오차의 직접 뺄셈 비교에는 한계가 있으며,
> 각 센서의 **자기 실걸음 대비 오차율**(−84% / −14%)로 읽어야 한다. 반복은 각 1세션(느린 보행).

- 느린 보행 케이던스 ≈ **68 steps/min** (평소의 60~70%). **발끌기 아님** — 발은 확실히 뗌.
- **각 세션 조건 / 로그:**
  - 만보기 세션: `steps=33 / 181s`. 세션 로그상 **소스=만보기가 정상 선택**됐고 앱 오류는 관찰되지 않음.
    (누적형 센서라도 listener 해제 전 미전달 배칭 이벤트가 있으면 마지막 관측값에 안 잡힐 수 있어
    "이벤트 유실 불가"로 단정하지는 않는다 — **배칭 지연은 제한사항으로 남김**. 다만 −84%는 배칭 몇 개로
    설명되는 크기가 아니라 결론을 바꾸지 않는다.)
  - 가속도계 세션: `steps=145 / 182s`.
  - 원본 로그: 리포 밖 로컬 보관(`waveform_local/`), 세션 식별자로 교차 참조 가능(요청 시 공유).

## 2. 판단

- **이 기기에서** 만보기는 저속 보행을 크게 과소계수했다. 만보기 펌웨어는 정상 케이던스에 튜닝돼 있어
  느린·약한 신호에서 성능이 급감하는 것으로 알려져 있고 이번 결과도 그와 일치하지만, **단일 기기 1세션**
  이라 펌웨어 내부 원인이나 기기 일반화는 단정하지 않는다(→ §6).
- 대상 사용자(65+)의 보행에 이 저속 대역이 흔히 포함되므로, **정상 속도 −2.4%보다 저속 과소계수가
  실사용 정확도에 더 크게 작용**할 것으로 본다.
- 가속도계는 같은 저속 세션에서 −14%로 버텼다. #89의 "무권한 가속도계" 원결정을 뒤집을 근거는 나오지
  않았다.

## 3. 결정

1. **#223(만보기 주 소스 전환) 철회** — 이 기기·시나리오에서 −84%는 대상 사용자에게 수용 불가.
2. **가속도계 유지**(#89 원결정) — 같은 저속 세션에서 −14%로 유일하게 버텼다.
3. **정상 속도 한정 보조 소스로도 남기지 않음** — "만보기를 쓸 수 있는 상황" 판정 자체가 가속도계 신호
   분석을 요구(순환 의존)하고, 세션 중 소스 전환은 단일 진실 소스 원칙과 상충 + `ACTIVITY_RECOGNITION`
   권한 비용 대비 이득이 정상 구간에 한정된다.
4. **저속 개선은 K2(#176 돌출도 적응형)** 로 — 오프라인 하네스에서 느린 보행 8/9 회복 입증됨.

## 4. K2(#176) 실기기 수용 목표선 (제안, 리뷰 반영)

- **느린·발 떼는 보행 |오차| ≤ 10%** (현행 −14% → 개선 확인)
- **정상 보행 18~22 / 20 무회귀**
- **발끌기는 오프라인 회복률(8/9)의 실기기 재현 확인**

## 5. 미래 로드맵 — 하이브리드 (참고, 별도 PR)

만보기를 정상 보행의 우수한 소스로 살리면서 저속 붕괴만 회피하는 구조. **K2로 가속도계 저속 감지가
안정화된 뒤** 착수한다(전환 조건이 가속도계 감지에 의존).

1. 세션 시작 직후 `PROBING` 구간에서 만보기·가속도계를 함께 관찰.
2. 만보기가 정상 증가 → `STEP_COUNTER` 확정.
3. 가속도계가 지속 보행(8~10보 상당)을 감지하는데 만보기 증가가 0~1보로 10~15초 지속 → `ACCELEROMETER` 확정.
4. 아직 안 걸은 단순 0보는 전환 근거로 쓰지 않음(반드시 가속도계 지속 보행 증거와 결합).
5. 확정한 소스는 세션 끝까지 고정 — 늦게 온 만보기 배칭 이벤트로 재전환 금지.
6. 두 센서 값을 합산·`max()` 로 섞지 않음. 확정 후 단일 소스만 화면·최종 snapshot·서버 업로드에 사용.
7. 권한 거부·만보기 미지원·시작 실패는 즉시 가속도계로 확정.

머지 순서: **#215(K3) → #176/K2 → 새 하이브리드 PR.**

## 6. 한계

- **단일 기기·단일 테스터**: SM-F766N 1대, 작성자 1인. 다른 OEM/칩셋의 만보기 펌웨어는 저속 특성이
  다를 수 있어 **복수 기기 미검증**이다.
- **비(非)paired 트라이얼**: 만보기·가속도계 수치는 동시 측정이 아니라 별도 세션이라, 센서 간 절대 오차의
  직접 비교가 아니라 각자의 오차율로만 해석해야 한다.
- **반복 수 적음**: 느린 보행은 각 1세션. 산포·재현 안정성은 확정되지 않았다.
- **배칭 지연 미배제**: 만보기 세션의 마지막 값에 미전달 배칭 이벤트가 빠졌을 가능성을 완전히 배제하지
  못했다(단, −84% 크기를 설명하지는 못함).
- **일반화 범위**: 이 데이터는 "이 기기에서 저속 시나리오 시 만보기 과소계수"를 보인 것이며, "65+
  사용자의 지배적 보행" 이나 펌웨어 내부 원인까지 입증하지는 않는다. **#223 철회라는 현재 RC 판단은
  이 제한을 밝혀도 유지**된다(가속도계를 뒤집을 근거가 없으므로).
