# 걸음 소스 실측 비교 — 하드웨어 만보기 vs 가속도계 (이슈 #89 / #223)

> **목적:** #89의 "무권한 가속도계" 걸음 소스 결정을, **실측 근거를 가진 결정**으로 고정한다.
> #223(하드웨어 만보기 `TYPE_STEP_COUNTER` 전환 제안)의 검증 과정에서 나온 비교 데이터를
> 보존한다. 원본 로그는 리포 정책상 리포 밖 보관, **여기엔 요약만** 남긴다.
> 나중에 같은 제안(만보기 전환)이 다시 나올 때 이 데이터가 시작점이다.

- **관련 이슈:** #89 (걷기 게이트, 원 결정) · #223 (만보기 전환 제안, **철회**) · #176/K2 (가속도계 저속 개선)
- **측정 기기:** Samsung SM-F766N (단일 테스터, 자연 보행)
- **측정일:** 2026-07-28

## 0. 요약 (한 줄)

**정상 속도만 보면 만보기가 우위(−2.4%)지만, 이 앱의 실제 사용자(65+)의 느린·발 떼는 보행 속도에서
하드웨어 만보기는 −84%로 붕괴하고 가속도계가 −14%로 훨씬 낫다.** → 만보기 전환(#223) 철회,
가속도계(#89 원결정) 유지, 저속 −14% 개선은 K2(#176 돌출도 적응형)로.

## 1. 실측 결과 (SM-F766N)

| 속도 대역 | 조건 | 만보기 (TYPE_STEP_COUNTER) | 가속도계 (현행) |
|---|---|---|---|
| **정상** | 3분20초, 실 250보 | 244 (**−2.4%**) | (4분 −24% / 10분 −22%) |
| **느린·발 떼는 보행** (65+ 대역) | 3분, 실 207보 | **33 / 207 (−84%)** 💀 | **145 / 169 (−14%)** |

- 느린 보행 케이던스 ≈ **68 steps/min** (평소의 60~70%). **발끌기 아님** — 발은 확실히 뗌.
- **로그 교차확인:**
  - 만보기 세션 `steps=33 / 181s` — 소스=만보기 정상 선택, 누적 절대값이라 이벤트 유실 불가
    → **하드웨어 자체가 느린 걸음을 못 잡는다**(전달 누락이 아님).
  - 가속도계 세션 `steps=145 / 182s`.

## 2. 판단

- **만보기 저속 붕괴는 하드웨어 특성**이다. 만보기 펌웨어는 정상 케이던스에 튜닝돼 있어, 발을 떼더라도
  느린·약한 신호는 걸음으로 확정하지 못한다. 문턱을 낮출 수 있는 소프트웨어 레이어가 아니다.
- 대상 사용자(65+)의 지배적 보행이 바로 이 저속 대역이므로, **정상 속도 −2.4%는 부차적 구간**이고
  −84%가 실사용 정확도를 지배한다.
- 가속도계는 저속에서도 −14%로 버틴다. #89의 "무권한 가속도계" 원결정이 대상 사용자 프로파일에서 옳았다.

## 3. 결정

1. **#223(만보기 주 소스 전환) 철회** — 대상 사용자에게 −84%는 수용 불가.
2. **가속도계 유지**(#89 원결정) — 저속 대역에서 유일하게 버틴다.
3. **정상 속도 한정 보조 소스로도 남기지 않음** — "만보기를 쓸 수 있는 상황" 판정 자체가 가속도계 신호
   분석을 요구(순환 의존)하고, 세션 중 소스 전환은 단일 진실 소스 원칙과 상충 + `ACTIVITY_RECOGNITION`
   권한 비용 대비 이득이 정상 구간에 한정된다.
4. **저속 −14% 개선은 K2(#176 돌출도 적응형)** 로 — 오프라인 하네스에서 느린 보행 8/9 회복 입증됨.

## 4. K2(#176) 실기기 수용 목표선 (제안, 리뷰 반영)

- **느린·발 떼는 보행(65+ 대역) |오차| ≤ 10%** (현행 −14% → 개선 확인)
- **정상 보행 18~22 / 20 무회귀**
- **발끌기는 오프라인 회복률(8/9)의 실기기 재현 확인**

## 5. 미래 로드맵 — 하이브리드 (참고, 별도 PR)

만보기를 정상 보행의 우수한 소스로 살리면서 저속 붕괴만 회피하는 구조. **K2로 가속도계 저속 감지가
안정화된 뒤** 착수한다(전환 조건이 가속도계 감지에 의존).

1. 세션 시작 직후 `PROBING` 구간에서 만보기·가속도계를 함께 관찰.
2. 만보기가 정상 증가 → `STEP_COUNTER` 확정.
3. 가속도계가 지속 보행(8~10보 상당)을 감지하는데 만보기 증가가 0~1보로 10~15초 지속 → `ACCELEROMETER` 확정.
4. 아직 안 걸은 단순 0보는 전환 근거로 쓰지 않음(반드시 가속도계 지속 보행 증거와 결합).
5. 확정한 소스는 세션 끝까지 고정 — 늦게 온 만보기 배칭 이벤트로 재전환 금지.
6. 두 센서 값을 합산·`max()` 로 섞지 않음. 확정 후 단일 소스만 화면·최종 snapshot·서버 업로드에 사용.
7. 권한 거부·만보기 미지원·시작 실패는 즉시 가속도계로 확정.

머지 순서: **#215(K3) → #176/K2 → 새 하이브리드 PR.**
