# 실기기 QA 워크스루 — 처음 하는 사람용

> **이 문서의 역할** — [qa-v1-rc-guide.md](qa-v1-rc-guide.md)(RC 가이드)가 "무엇을 어떤 ID로
> 판정하고 증거를 어디에 남길지"의 **기준 문서**라면, 이 문서는 **"폰에서 정확히 어디를 눌러
> 어떻게 확인하는지"** 를 손순서 단위로 풀어쓴 실행 안내다. 판정 ID·필수 세트·증거 템플릿은
> 전부 RC 가이드를 따른다 — 여기서 새 ID를 만들지 않는다.
>
> 대상 독자: QA를 처음 하는 팀원. adb 를 써 본 적 없어도 §0부터 따라 하면 된다.

---

## 0. 처음 한 번만: 장비 준비

### 0.1 폰을 "개발자 모드"로

1. 폰 **설정 → 휴대전화 정보 → 소프트웨어 정보** → **빌드번호를 7번 연타** → "개발자 모드가
   켜졌습니다" 토스트 확인.
2. 설정 맨 아래 생긴 **개발자 옵션** → **USB 디버깅** ON. (무선 디버깅을 쓰려면 같은 화면의
   **무선 디버깅** ON → "페어링 코드로 기기 페어링" → Mac에서 `adb pair <ip:port>` 후 `adb connect`.)

### 0.2 Mac 연결 확인

```bash
adb devices        # 기기 시리얼 + "device" 가 보이면 성공
```
- `unauthorized` 로 뜨면: 폰 화면의 "USB 디버깅 허용?" 팝업에서 **허용**을 누른다.
- 아무것도 안 뜨면: 케이블(충전 전용 케이블 주의)·무선 디버깅 연결을 다시 확인.

### 0.3 APK 설치·삭제·해시 (복붙용)

```bash
adb install -r AH0404-release.apk        # 설치(-r: 기존 앱 위에 업데이트 설치)
adb uninstall com.aihealthcare.ah0404    # 완전 삭제(계정·설정·기록 전부 날아감 — §0.5 주의)
shasum -a 256 AH0404-release.apk         # 기준점 기록용 SHA-256
```

### 0.4 증거 남기기 (로그·스크린샷·녹화)

```bash
adb logcat -c                                        # 테스트 시작 전 로그 비우기
adb logcat > qa_$(date +%m%d_%H%M).log               # 수집 시작(끝낼 땐 Ctrl+C)
adb exec-out screencap -p > shot_$(date +%H%M%S).png # 스크린샷
adb shell screenrecord /sdcard/qa.mp4                # 녹화(Ctrl+C 종료) → adb pull /sdcard/qa.mp4
```
폰 자체 스크린샷/녹화 기능을 써도 된다. **FAIL 은 반드시 3종 세트**: 스크린샷(또는 녹화) +
logcat 파일 + 재현 손순서.

### 0.5 ⚠️ 앱 데이터를 아무 때나 지우지 말 것

RC 가이드 **§2.5 픽스처 표**가 기준이다. 요지: **"앱 삭제/데이터 삭제 = 그동안 만든 계정 상태
리셋"** 이므로, 기록 있는 계정(F-EXIST)을 만들어 두면 그 상태가 필요한 시나리오가 끝날 때까지
지우지 않는다. 초기화는 "신규 상태가 필요한 그룹을 시작할 때"만.

## 1. 화면 지도 (이 문서의 용어 = 실제 화면 문구)

| 용어 | 실제 화면 |
|---|---|
| **시작 화면** | Google·Kakao 로그인 버튼 + **"체험으로 시작하기"** |
| **하단 탭** | **홈 · 미션 · 기록 · 설정** 4개 |
| **홈** | 오늘의 미션 요약, 펫, **"영상 따라 운동하기"** 버튼, **"나의 기록 보기"** |
| **미션 탭** | 걷기 챌린지 · 운동 · 식사(단백질) · 게임 카드 |
| **운동 화면** | 상단 4탭: **몸풀기 · 근력 운동 · 서서 운동 · 마무리**. 근력/서서는 **포스터를 탭 → 가로 전체화면**(좌상단 **✕ 닫기**), 몸풀기/마무리는 **"운동 시작하기"** → 단계별 루틴 플레이어 |
| **안전 고지 팝업** | 운동을 이 화면 방문 중 처음 시작할 때 1회: "🧡 운동 전, 안전하게 준비해요" → **"네, 확인했어요"** |
| **설정 탭** | 글자 크기 · 소리 크기 · **운동 난이도(가볍게/보통/힘차게)** · 로그아웃 등 |

## 2. 시나리오 워크스루

각 절 형식: **[매핑 ID]** → 준비 → 손순서 → **여기를 보면 PASS** → 증거. 판정 기록은 RC 가이드
§6 템플릿으로 #100 댓글에 남긴다(서버·배포 항목은 #244).

### W-A. 신규 설치·첫 실행 — [#244 §1, GP-01 진입 전]

준비: `adb uninstall com.aihealthcare.ah0404` (있었다면), release APK 파일.

1. `adb install -r AH0404-release.apk` → 폰 앱 서랍에서 아이콘 탭.
2. 시작 화면이 뜨는지, 뜨기까지 크래시·검은 화면이 없는지 본다.
3. `adb logcat` 을 미리 켜 두고 실행하면 R8(코드 축소) 관련 크래시가 바로 잡힌다 —
   `FATAL EXCEPTION` 이 없어야 한다.

**PASS**: 설치 성공 + 시작 화면 정상 표시 + FATAL 로그 0건.

### W-B. 로그인·온보딩 — [GP-01 앞부분, ONB-01~02, #267]

준비: W-A 직후의 신규 상태.

1. **"체험으로 시작하기"** 탭. (Google/Kakao 를 시연 범위에 넣기로 했다면 소셜 버튼도 각각 1회 —
   release 서명 키해시가 콘솔에 등록돼 있어야 성공한다. 실패하면 그 자체가 §1 키해시 항목 FAIL.)
2. 약관 동의 → 온보딩 진입. 프로필(생년월일·성별·키·몸무게·허리둘레) 입력.
3. **활동 입력(#267 신규 확인 포인트)** — "일주일에 며칠 걷기 운동을 하세요?" / "일주일에 며칠
   근력 운동을 하세요?" 스테퍼에서:
   - 아무것도 안 고르고 다음 → **"걷기·근력 운동 일수를 선택해 주세요."** 로 제출이 막히는지
   - **0일을 명시적으로 선택**하면 통과되는지 (미응답과 0일은 다른 상태다)
   - 상한: 걷기 **7일**, 근력 **5일** 이상으로 올라가지 않는지
   - **화면 재생성 후 값 유지**: 온보딩 중엔 앱 하단 탭에 못 가므로 **시스템 설정**으로 재생성을
     일으킨다 — 값을 고른 상태에서 홈 버튼 → **Android 설정 → 디스플레이(기기에 따라 접근성) →
     글꼴 크기**를 한 단계 변경 → **최근 앱 버튼으로 AIGO 복귀**. 글꼴 변경은 화면을 재생성시키므로,
     복귀했을 때 고른 일수가 그대로면 PASS(초기화돼 있으면 FAIL). 확인 후 글꼴 크기는 원래대로.
4. 5STS 측정 또는 스킵 → 홈 진입.

**PASS**: 위 4개 모두 기대대로 + 홈 도달. 이 계정이 이후의 **F-EXIST** 가 되므로 지우지 말 것.

### W-C. 골든 패스 — [GP-01]

> ⏱ 걷기 목표는 난이도별 **당일 누적 시간**(easy 20 / normal 30 / hard 40분)이다. 실제로 걸어야
> 하므로 시간이 든다. **나눠 걸어도 하루 합산**되니 중간에 끊어도 된다.

1. 홈에서 오늘의 미션 요약 확인 → **미션 탭** → 걷기 챌린지 시작.
2. 알림 권한 팝업이 뜨면 **허용** (걷기 측정 중 상단바에 "걷기 측정 중 · N보" 알림이 떠야 정상).
3. 목표 달성 → 완료 저장 → 홈·기록 탭에 걸음/포인트 반영 확인.
4. **앱 완전 종료**(최근 앱 목록에서 위로 스와이프) → 재실행 → 로그인 화면이 아니라 **홈으로
   바로 복귀**하고 기록이 그대로인지.

**PASS**: 저장 1회(중복 없음) + 홈/기록 반영 + 재실행 복원.

### W-D. 운동 영상 — [EXER-01~04 + #258/#254/#265 신규 확인 포인트]

1. **진입 2경로가 같은 화면인지** [EXER-01]: 홈 **"영상 따라 운동하기"** 와 미션 탭 운동 카드
   → 둘 다 4탭 운동 화면.
2. **안전 고지 1회** [#265]: 이 화면에서 처음 시작(포스터 탭이든 "운동 시작하기"든) 때 팝업 →
   "네, 확인했어요" → 같은 방문 중 두 번째 시작부터는 안 뜬다. 화면을 나갔다 재진입하면 다시 1회.
3. **근력 운동 탭** → 포스터 탭 → **가로 전체화면 자동 재생** [#254]. 좌상단 ✕ 닫기 → 세로 복귀,
   탭이 근력 운동에 **그대로**(몸풀기로 리셋되면 FAIL).
4. **완료 집계(#258 — 이번 RC 신규)**: 근력/서서 영상을 합계 10분 이상 실제 재생(일시정지 시간은
   미포함) 후 닫기 → 홈 '오늘의 미션'에서 운동 미션이 진행/완료로 반영되는지. 기록 탭에도 반영.
5. **배속** [EXER-02]: 설정 탭 → **운동 난이도**를 힘차게로 → 재생 속도가 빨라지는지(음정 유지).
6. **몸풀기/마무리 루틴**: "운동 시작하기" → 단계 진행. '다음'으로 스킵해 보고, 중도 종료
   팝업의 "나가기"도 확인("지금까지 진행한 시간은 저장돼요").
7. **비행기 모드** [EXER-04]: 비행기 모드 ON → 몸풀기 루틴이 재생되는지(번들이라 오프라인 가능).
   근력(스트리밍)은 오류 화면 대신 **안내+재시도**가 떠야 한다.
8. 같은 영상 **3회 반복** 재생 → 크래시·심한 발열 없음 [#244 §3].

9. **이어보기·오늘 누적 카드(#235 → PR #280 수정분)** — RC 에 #280 이 포함되면(동결표 확인)
   이 항목은 **정식 PASS 항목**이다:
   - 전체화면에서 몇 분 재생 → ✕ 닫기 → 같은 포스터 다시 탭 → **처음이 아니라 보던 위치에서
     이어서** 재생되는지
   - 운동 화면에 **오늘 누적 운동시간** 카드가 표시되고, 방금 본 시간이 반영돼 있는지
   - (#280 **미포함** 구빌드에서만 기지 이슈 — 그 경우에 한해 FAIL 대신 비고에 "#235/#280 대기"로 적는다)

**PASS**: 1~9 각각. 특히 4번(집계)·9번(이어보기·누적)은 이번 RC의 핵심 신규 배선이다.

### W-E. 걷기 상세 — [WALK-02~07]

1. 걷기 측정 시작 → **전원 버튼으로 화면 끄고 주머니에 1~2분** → 켜서 걸음이 계속 누적됐는지
   [WALK-02]. 상단바 알림 "걷기 측정 중 · N보"도 확인.
2. 측정 중 홈 버튼으로 나갔다 복귀, 전화 수신 후 복귀 → 측정 연속 [WALK-03].
3. 측정 중 Wi-Fi 끄고 LTE 로 → 종료 저장 정상 [WALK-04].
4. 0걸음으로 그냥 종료 → 축하가 아닌 중립 안내 [WALK-05].
5. 시작·달성 시 음성/진동이 **각 1회만** [WALK-06]. 설정 탭 **소리 크기**를 줄이면 음성도
   작아지는지(#237 배선).

### W-F. 식사(단백질) 기록 — [MEAL-02~07]

1. 미션 탭 식사 카드("눌러서 기록하기") 진입.
2. **1종만 선택 → 저장** → 목표 달성 + 포인트 [MEAL-03].
3. 재진입 → 이전 선택 복원 [MEAL-05]. 카테고리 바꿔 재저장 → 포인트 **추가 적립 없음** +
   "이미 반영" 문구 [MEAL-06].
4. (별도 계정 필요) 온보딩 건강체크에서 신장질환 선택 시 식사 미션 자체가 **안 보여야** 함 [MEAL-01].

### W-G. 게임 — [GAME-01~02]

미션 탭 게임 카드 → 영상 재생·끝까지 시청. **완료 처리·포인트 미반영은 v1 정상 동작**(post-v1)
이므로 FAIL 아님.

### W-H. 기록 탭·대시보드·펫 — [DASH-01, PET-01~02, REC]

1. 홈 "나의 기록 보기" 또는 하단 **기록** 탭 → 오늘/누적 기록 표시.
   (#275 기록 탭 개편이 이번 RC에 포함되면: 나의 기록 통계 + 근육 건강 점수 + 내 정보 편집
   화면이 뜨는지, 편집 저장 후 값 유지되는지 추가 확인.)
2. 예측 대시보드 로드·개인화 값 [DASH-01]. 비행기 모드에선 오류 화면 대신 안내+재시도.
3. 홈 펫: 스크롤·탭 전환 반복에도 깨짐/크래시 없음 [PET-01].

### W-I. 업데이트 설치 경로 — [#244 §1]

1. **직전 RC APK**를 먼저 설치·로그인해 둔 상태에서, 새 RC APK 를 `adb install -r` 로 **삭제 없이**
   덮어 설치.
2. 실행 → 재로그인 요구 없이 세션 유지, 설정(글자·소리·난이도)·기록 유지.

**PASS**: 데이터 초기화·강제 로그아웃 없음.

### W-J. 강제종료·안정성 — [#244 §4 일부]

1. 사용 중 최근 앱에서 스와이프로 강제종료 → 재실행 → 홈 복원.
2. 걷기+영상 10~20분 연속 사용 → 폰이 뜨겁거나 배터리가 급감하거나 측정이 끊기지 않는지.

### W-K. Logcat 민감정보 — [AUTH-08, #244 §1]

W-B~W-D 를 도는 동안 §0.4 로 받아 둔 로그 파일에 대해:

```bash
grep -icE "id_token|access_token|authorization: bearer|password|주민|건강정보" qa_*.log
```

**PASS**: 0건. (서버 쪽 로그는 2026-07-30 #244 댓글에서 이미 0건 확인 — 폰 쪽만 보면 된다.)

### W-L. 발표장 스모크 — [#244 §4·§5]

발표 장소에서: 발표장 Wi-Fi 로 골든 패스 1회 → LTE 핫스팟으로 1회(연속 2회 성공 기준).
기기 설정 고정(밝기 최대·자동회전 OFF·방해금지 ON·절전 OFF). 대체수단(정상 동작 녹화본,
직전 정상 APK)을 기기에 보관. 상세 항목은 #244 §4·§5 체크리스트를 그대로 따른다.

## 3. 기록 규칙 요약 (이것만 기억)

1. 판정은 4가지뿐: **PASS / FAIL / BLOCKED / N/A(사유)**. 안 돌린 항목은 조용히 넘기지 말고
   **반드시 N/A 로 기록**한다.
2. FAIL 은 **3종 세트**(스크린샷·logcat·재현 손순서) + blocker 여부.
3. 결과는 RC 가이드 **§6 템플릿**을 복사해 **#100 댓글**로. 서버·배포·발표장 항목은 **#244 댓글**로.
4. 기지 이슈 처리는 **RC 동결표 기준**: 수정이 **이번 RC 에 미반영**인 기지 이슈만 FAIL 대신
   비고(이슈 번호)로 적는다. 수정이 RC 에 **포함**된 이슈는 반대로 **정식 검사 대상**이다 —
   예: #235 는 #280 포함 빌드면 W-D 9번 PASS 항목, 미포함 구빌드에서만 비고 처리.
