## 0. 결론 (한 줄)

**돌출도 적응형 + 짧은 진입(need=5)은 느린·손 파지 보행의 0계수를 회복시키지만, 같은 파라미터가
앉기 전환·순수 앉기의 오탐을 같은 방향으로 키운다.** 회복과 과다계수는 현재 관측 신호에서 **같은
축**이라, 피크 특징(진폭·돌출도·리듬·자세)만으로는 두 동작을 분리할 수 없다. → K2는 v1 운영 미적용,
연구 보류.

## 1. 회복 결과 — 돌출도 적응형 + 짧은 진입(need=5)

고정 임계값(현행 `WalkingStepDetectorLogic`, DEFAULT_PEAK_THRESHOLD=10.5)은 손 파지 시 진동이
주머니의 1/3~1/4로 약해 임계를 못 넘고 리듬 상태머신이 IDLE에 갇혀 **계수 0**이 된다. 돌출도 적응형은
중력 제거(EMA) 후 국소 최저→최고 상승폭(prominence)에 **동적 문턱**(`max(FL, PR·prominence_EMA)`)을
걸어, 약하지만 규칙적인 피크를 살린다.

| 라벨 | 현행(고정임계) | 돌출도 적응형 need=5 |
|---|---|---|
| normal_walk (정상) | 기준 | **−6%** (실용 수준) |
| shuffle_walk (발끌기) | 큰 과소·0계수 다수 | **+4%**, 0계수 소멸 |
| 0계수 트라이얼 | 다수 | **0건** |

→ **#176의 본 타겟(느린·손 파지 0계수 회복)은 need=5에서 달성됨.**

## 2. §4 분리력 분석 — 앉기 전환 버스트는 피크 수준에서 보행과 판박이

`walk_then_sit` 트라이얼에서 돌출도 피크를 보행 구간 / 앉기 전환 구간으로 나눠 피크별 특징을 비교했다
(리포 밖 로컬 분석).

| 특징 | 보행 피크 | 앉기 전환 피크 | 분리 가능? |
|---|---|---|---|
| 돌출도(prominence) 중앙값 | ~0.76 | ~0.62 | ❌ 크게 겹침 |
| 국소 동적 RMS(±0.5s) | ~2.12 | ~1.46 | ❌ 문턱 걸면 보행도 손실 |
| 구간 간격 변동계수 CV | ~0.76 | ~0.65 | ❌ 앉기가 더 불규칙하지도 않음 |
| 자세(중력축) 변화 각도 | — | 2.8°~73° (배치 편차 큼) | ⚠️ 손 파지 전용 보조로만 |

- 앉기 phase에 **약 11 peaks/trial**이 **2.2Hz(보행 케이던스대)** 로 생성 → 앉는 동작의 흔들림이
  걸음과 진폭·리듬 모두 흡사.
- 국소 RMS 문턱을 걸어 앉기 피크를 지우려 하면 **보행 피크도 같은 비율로 손실**된다(단일 문턱으로
  분리 불가).
- 자세 변화는 손 파지 케이스에서만 신호가 되고, 배치에 따라 2.8°~73°로 **일관되지 않아** 1차 분리
  신호로 못 씀.

→ **개별 피크의 모양으로는 보행/앉기전환을 못 가른다.**

## 3. 게이트 C 격자 — 진입(need) × 소급창(retro_win)으로도 동시 달성 불가

진입 임계 `need`(짧을수록 회복↑)와 정지 선언 후 소급 취소창 `retro_win`을 2손잡이로 스윕했다.
회복(normal·shuffle·0계수)과 `walk_then_sit ≤+2`를 **동시에 만족하는 조합이 없다.**

```
need |  norm오차 norm0 |  sitFP           sit계수 | wts최악
   5 |    -6%    0    |   5   [0,13,7,11,5,5]    |  +16
   6 |    -6%    0    |   3   [0,13,7, 6,0, 0]   |  +11
   7 |    -6%    0    |   2   [0, 7,7, 0,0, 0]   |   +8
   8 |   -14%    1    |   0   [0, 0,0, 0,0, 0]   |   +8
  10 |   -23%    1    |   0   [0, 0,0, 0,0, 0]   |   +8
```
(retro_win=3.0s 고정. norm오차=normal 평균오차%, norm0=normal 0계수 건수, sitFP=sit_only 6개 중 오탐 건수, wts최악=walk_then_sit trial별 최악 과다계수)

- 회복이 좋아지는 방향(need↓)이 **정확히** 앉기 오탐이 커지는 방향과 같다.
- retro_win을 3→6s로 넓혀도 walk_then_sit 최악은 +16→+12 수준에서 멈추고 실걸음까지 지운다.

## 3.5 ⚠️ 정정 — sit_only 오탐: 이전 게이트 C 게시의 오류

**이전 #176 게시글에서 "게이트 C: need=5로 sit FP 0"이라 보고했으나 이는 틀렸다.**
당시 요약 스크립트가 sit_only(정답=0)를 `man not in (None, 0)` 필터로 **집계에서 제외**해 FP가 항상
0으로 보인 버그였다. 재측정 결과 **need=5에서 sit_only 6개 중 5개가 오탐**(계수 13·7·11·5·5)이다.

이 정정은 결론을 **약화하지 않고 강화**한다: sit_only FP도 `need`에 **회복과 같은 방향으로 결합**한다
(need↓ → 회복↑ 그리고 앉기 오탐↑). sit_only FP=0은 need≥8에서만 나오는데, 그때 회복이 붕괴한다
(normal −14%, 0계수 재발). 즉 **순수 앉기 오탐도 walk_then_sit과 같은 "정지 구간 신호 비분리" 문제**의
또 다른 표출이며, 짧은 진입 단독으로는 회복과 앉기 오탐 0을 양립할 수 없다.

## 4. 종합 판단

- 회복(느린·손 파지)과 과다계수(walk_then_sit + sit_only)는 **현재 신호에서 같은 축**이다.
- 이론적으로 남은 분리 정보는 피크 모양이 아니라 **미래 시간 정보**(그 뒤에 보행이 이어지지 않고
  지속 정지로 수렴하는가) 뿐 — 즉 temporal / stillness 기반 사후 판별.
- 그러나 temporal 경로는 **계수 표시 지연**과 **실제 마지막 걸음 삭제 위험**이라는 새 비용을 만든다.
- 걷기 미션 성공은 이미 **시간 기반(20분 누적)** 이라, #176의 실피해는 "미션 누락"이 아니라
  **"0보 표시의 신뢰 문제"** 로 좁혀진다. 걸음 수를 참고 지표로 강등하면 잔여분은 제품 수준에서 수용
  가능하고, 표시 문제는 저비용 UX(#232)로 완화한다.

→ **v1: 현행 가속도계 + K3 유지, K2 운영 미적용(연구 보류), 걸음 수 = 참고 지표.**

## 5. 재개 시 첫 연구 후보 — stillness 기반 미확정 꼬리 취소 (지금 구현 안 함)

재개 조건이 충족되면 검토할 **첫** 후보로만 기록한다(활성 이슈로 열지 않음).

- 후보 피크를 즉시 확정하지 않고 **최근 꼬리를 PROVISIONAL 버퍼**에 보관
- `PROVISIONAL → COMMITTED`(보행 지속) 또는 `PROVISIONAL → DISCARDED`(지속 정지 감지) 단일 경로
- 지속 정지 감지 시 **마지막 안정 보행 윈도우 이후의 전환 꼬리만** 취소(단순 "최근 5초 삭제"는 실걸음
  제거 → 금지)
- 화면에는 가능하면 committed 걸음만 노출(숫자 감소 UX 회피)
- **K3와의 경계:** 전환 구간은 후보/취소 메커니즘이 1차, K3 소급차감은 **확정분만**(후보 ID로 이중
  차감 방지)
- **결합 금지:** 스톱게이트·검출기의 확정 결과를 직접 참조하지 않고 **MotionContext(원 특징)만 공유**
- **자세(중력축) 변화는 손 파지 전용 보조 신호로만**

### 재개 시 필요한 데이터·평가

- 다음 수집분에 `walk_end` / `sit_start` 시점 라벨 전제(경계 정답)
- 시나리오: ①정상 ②손 파지 느린 ③발끌기 ④걷기→앉기 ⑤걷기→잠시정지→재보행 ⑥느린보행→정지 ⑦sit_only
- 특히 **⑤걷기→잠시정지→재보행**에서 실걸음 보존·재웜업 반복 없음 검증
- 상쇄 분리 측정: 앉기 전 보행 recall과 앉기 후 false step을 **별도 집계**
- 첫 계수 표시 지연 / 최종 확정 지연 기록
- 파라미터 고정 후 **튜닝 미사용 참여자·기기 홀드아웃**

## 6. 재개 조건 (K2 전용)

다음 중 최소 하나의 **새 정보 또는 제품 결정**이 생길 때만 재개한다.

1. 튜닝에 사용하지 않은 **실제 고령 사용자·새 참여자·새 기기의 정답 데이터** 확보
2. 자이로·OS `TYPE_STEP_COUNTER`·Activity Recognition 등 **추가 센서 신호** 사용 결정
3. provisional 계수로 인한 **수 초 표시 지연을 제품 UX가 허용**한다는 합의
4. 느린/손 파지 걸음 정확도가 **출시 필수 요구사항**으로 재확정되고 연구 비용 배정
5. `walk_then_sit` 오탐과 느린 보행 누락 중 **어느 쪽을 우선할지 제품 수준 허용 오차 합의**

이 조건 없이 **같은 파형에 규칙만 더 붙이는 것은 중단**한다(소규모셋 과적합·상태머신 복잡도 증가).
