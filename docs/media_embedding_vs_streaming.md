# 미디어 내장(res/raw·assets) vs 스트리밍(서버 /videos) 선택 기준 (#347)

콘텐츠를 추가할 때마다 "내장할지 스트리밍할지"를 매번 다시 고민하지 않도록, 지금까지의 실제 결정에서
기준을 추출해 남긴다. 현재의 혼합 구성은 우연이 아니라 아래 기준의 일관된 결과다.

## 결정 기준

**내장(res/raw·assets)을 선택한다:**
1. **짧은 루프 클립을 조합해 긴 콘텐츠를 만드는 경우** — 루틴(몸풀기·마무리)은 1-3초 루프 클립
   (각 0.2-0.6 MB)을 단계로 조합해 총 2-3 MB로 4분 콘텐츠를 만든다. 완결형 영상(서버의 미사용
   `warmup.mp4` = 44 MB) 대비 압도적으로 유리 — 팀이 이미 같은 판단으로 전환한 사례.
2. **오프라인/네트워크 무관 동작이 요구되는 핵심 경로** — 루틴 재생, 5STS 가이드(`sts_loop.mp4`),
   펫 애니메이션. 시니어 환경(불안정한 Wi-Fi)에서 운동 시작이 네트워크에 막히면 안 된다.
3. **재생 빈도가 높고 크기가 작은 자산** — 매 진입마다 쓰는 짧은 클립은 캐시 워밍업 비용도 아깝다.

**스트리밍(서버 /videos + CacheDataSource 캐시)을 선택한다:**
1. **완결형·길이가 긴 영상** — 근력(7.0 MB)·유산소(17.3 MB)·미니게임(4.6 MB). 내장하면 APK가
   콘텐츠 수에 비례해 커진다(현재 APK 50.1 MB — 스트리밍 3종을 내장하면 +29 MB).
2. **교체 주기가 있는 콘텐츠** — 서버 파일 교체만으로 배포 없이 갱신(파일명 버전으로 캐시 무효화, #283).
3. **전제 조건**: 재생 실패 안내·재시도 처리(#345)가 있어야 한다. 스트리밍은 실패가 정상 시나리오다.

**경계 사례 판단법**: "이 콘텐츠가 안 나오면 미션 수행 자체가 막히는가?"가 예이면 내장을 우선 검토하고,
크기 때문에 내장이 어려우면 스트리밍 + 실패 안내(#345) + (필요시) 사전 캐싱을 조합한다.

## 이어보기(resume) 비대칭 — 현황과 근거

| 화면 | 이어보기 | 이탈 확인창 |
|---|---|---|
| 근력·유산소 (스트리밍) | ✅ 위치 보관·복원(#235) | 없음 (이어보기가 있어 불필요) |
| 루틴 (내장 조합) | ❌ 없음 — 중단 시 처음부터 | ✅ 있음 (비가역이라 방어) |
| 미니게임 (스트리밍) | ❌ autoPlay 매번 처음부터 | 없음 |

- 확인창 유무의 비대칭은 **이어보기 유무의 차이에서 비롯**된 것으로 현 설계는 타당하다.
- 루틴 플레이어의 '이전 동작' 버튼·전체 진행 표시는 #335→#338 로 구현 완료(2026-07-31 머지).
  **'중단 지점 이어하기'(세션 간 resume)는 여전히 미구현**으로, 실수 이탈은 확인창이 방어한다.
  니즈가 확정되면 별도 이슈로 다룬다(이 문서의 범위(기준 문서화) 밖).
- 미니게임은 짧은 단일 영상이라 이어보기 필요성이 낮다(#344 종료 자동 복귀로 충분).
