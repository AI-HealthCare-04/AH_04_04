# 사용자 피드백 활용 루프 (#357 경량 C)

심사 3-4 "수집한 데이터를 지속적인 개선에 이용" 대응 문서. 재학습 파이프라인이 아니라
**"수집 → 집계 → 검토 → 개선 결정 기록 → 전후 비교"** 의 경량 루프를 운영한 근거를 남긴다.

## 1. 데이터 정의 (팀 결정, 이슈 #357)

- 수집: 근육 건강 점수 화면에서 새 예측(prediction_id)당 1회, "이 결과가 평소 느끼는 몸 상태와 비슷한가요?"
  (비슷해요 / 잘 모르겠어요 / 다르게 느껴져요, '다르게'는 선택 사유 too_high/too_low/other).
- 저장: `prediction_feedbacks` — `prediction_id` FK+UNIQUE 로 `risk_predictions` 의
  입력 피처·점수·모델 버전 스냅샷과 1:1 연결(복제 없음).
- **성격: 주관적 체감·수용도 신호.** 예측을 본 뒤 응답하므로 결과에 영향받는 편향이 있다.
  모델 정확도·정답 라벨로 쓰지 않고, 재학습에 직접 투입하지 않으며,
  **불일치가 높은 구간을 찾아 추가 검증하는 후보 신호**로만 쓴다.
  (참고: FDA PRO 지침 — 측정 도구는 사용 목적에 맞는지 검토해야 한다)
- 게스트 포함(provider 는 users 조인으로 구분). **시연·QA 응답은 `is_test=1` 로 마킹해
  실제 사용자 N 에서 제외한다** — 마킹 없이 집계에 섞지 않는 것이 원칙.

## 2. 집계 방법

```bash
uv run --no-sync python -m scripts.feedback_report
```

모델 버전 × 점수 구간(score_band)별 응답 분포·불일치율(different/전체)·사유 분포와
provider 별 응답 수를 출력한다(읽기 전용). 출력 표를 이 문서 §4 에 그대로 붙인다.

## 3. 검토 절차 (불일치율이 높은 구간이 나오면)

1. 해당 구간 응답의 `risk_predictions.input_snapshot` 을 표본 검토 — 입력 이상(극단값·기본값 잔류) 여부
2. 원인 후보 분류: 입력 안내 문제 / 결과 설명 문제 / 점수 구간 임계값 / 모델 자체
3. 개선 결정과 근거를 §4 에 기록하고, 코드 변경이면 이슈·PR 링크를 남긴다
4. 변경 배포 후 같은 집계를 다시 돌려 전후 비교를 §4 에 추가한다
